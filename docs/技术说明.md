# ZenMind — 技术说明与开发参考

面向开发者与运维：技术栈、目录结构、本地开发、环境变量、ETL、容器与部署、HTTP API 摘要。

---

## 技术栈

| 层级 | 技术 |
|------|------|
| 后端 | Go 1.25、Gin、GORM（PostgreSQL + MySQL） |
| 前端 | React 18、TypeScript、Vite 6、Ant Design 5、React Router 7、Zustand |
| 容器 | 多阶段 Dockerfile（后端 Alpine 二进制；前端 Nginx 托管静态资源并反代 `/api`） |

## 仓库结构

```
ZenMind/                     # 根目录名可与 Git 仓库名一致
├── backend/                 # Go API 与 ETL
│   ├── cmd/server/          # 入口
│   ├── internal/            # config、db、handlers、etl、scheduler、models …
│   ├── config/etl_tables.yaml
│   ├── migrations/001_init.sql
│   └── Dockerfile
├── frontend/                # React SPA
│   ├── src/
│   ├── nginx.conf           # 生产环境：SPA + /api → backend:8080
│   └── Dockerfile
├── docker-compose.yml       # 默认拉 Docker Hub 镜像并编排 PG + Redis
└── docker-compose.build.yml # 可选：从源码构建前后端（与 compose.yml 叠加）
```

## 前置条件

- **本地开发（非 Docker）**：**PostgreSQL**（建议 15+）、Go、Node.js。
- **Docker 一键启动**：仅 **Docker**；编排会拉起 PostgreSQL 与 Redis。
- 可访问的 **禅道 MySQL**（只读即可；表名可能因禅道版本不同，需在 ETL 配置中调整）。同步前可在界面配置数据源。

Docker Compose 仍包含 **Redis** 服务（当前后端定时同步已改为进程内定时器，不依赖 Redis）。

## 本地开发

### 1. 初始化数据库

创建数据库与用户后，执行迁移：

```bash
psql "$PG_DSN" -f backend/migrations/001_init.sql
```

（`PG_DSN` 与仓库根目录 `.env.example` 中格式一致，或直接使用 `psql` 连接串。）

### 2. 后端

在仓库根目录准备环境变量（与 Docker Compose 共用同一文件）：

```bash
# 在仓库根目录
cp .env.example .env
# 编辑 .env：PG_DSN、REDIS_ADDR、ADMIN_*、JWT_SECRET 等

cd backend
go run ./cmd/server
```

默认监听 `PORT`（未设置时为 `8080`）。

### 3. 前端

```bash
cd frontend
npm install
npm run dev
```

开发服务器默认 **5173**，并通过 Vite 将 `/api` 代理到 `http://localhost:8080`。

### 4. 登录

使用 `.env` 中的 `ADMIN_USER` / `ADMIN_PASS` 在 `/login` 登录。

### 5. 命令行报工（zmcli）

后端镜像或本地构建产物内含 **`zmcli`**，经 ZenMind API 代发禅道报工：

```bash
export ZENMIND_URL=http://localhost:8080
export ZENMIND_USERNAME=admin
export ZENMIND_PASSWORD='***'
zmcli effort -task 12345 -work "联调" -consumed 2 -left 6
```

（Docker 内：`docker compose exec backend ./zmcli effort ...`）

## 环境变量

完整说明见仓库根目录 [`.env.example`](../.env.example)。常用项：

| 变量 | 说明 |
|------|------|
| `PORT` | HTTP 端口，默认 `8080` |
| `WEB_PORT` | 前端对外端口（宿主机端口 → 容器 Nginx 80），默认 `2024` |
| `DOCKERHUB_NAMESPACE` | Docker 编排拉取前后端镜像时的命名空间，默认 `techxtry` |
| `ZENMIND_IMAGE_TAG` | 上述镜像的标签，默认 `latest` |
| `PG_DSN` | PostgreSQL 连接串 |
| `REDIS_ADDR` | Redis 地址，如 `localhost:6379` |
| `ADMIN_USER` / `ADMIN_PASS` | 管理员登录 |
| `JWT_SECRET` | JWT 签名密钥 |
| `ZT_HOST` 等 | 可选；禅道 MySQL，也可仅在前端「系统配置」填写 |
| `ETL_CONFIG_PATH` | ETL 映射文件路径，默认 `config/etl_tables.yaml`（相对后端工作目录） |
| `SYNC_INTERVAL_MINUTES` | 增量 ETL 周期间隔（分钟），默认 15；可在系统配置页覆盖 |
| `EFFORT_RECONCILE_ENABLED` | 是否启用每日报工回刷，默认 `true` |
| `EFFORT_RECONCILE_HOUR` | 报工回刷执行时刻（本地时区 0–23 点），默认 `3` |
| `EFFORT_RECONCILE_DAYS` | 报工回刷日历窗口（天），默认 `180`（与界面 6 个月查询上限一致） |

修改 `config/etl_tables.yaml` 后需**重启后端**。

## ETL 配置

[`backend/config/etl_tables.yaml`](../backend/config/etl_tables.yaml) 定义源表（禅道 MySQL）到目标表（PG `local_*`）的映射，以及水印类型：`none`（全量覆盖）、`time`、`id`。部分禅道版本表名不同（例如工时表），请按实际库表调整 `source` 与 `extra_filter`。

**报工同步分两条链路（可并行，同类任务互斥）：**

| 链路 | 触发 | 作用 |
|------|------|------|
| 增量 | 定时 `RunAll`（间隔见 `SYNC_INTERVAL_MINUTES` / 系统配置） | 按 id 拉新 + 最近约 5000 条 id 对账删除；`zt_action`/`zt_history` 每 4 轮全量拉一次以缩短单次耗时 |
| 报工回刷 | 每天本地时间 `EFFORT_RECONCILE_HOUR`（默认 03:00） | 按日历窗口（默认近 180 天）从禅道回刷报工，覆盖在禅道 UI 中修改日期、工时等 |

增量与报工回刷**可同时执行**（手动回刷报工不必等增量结束）。同一类任务不能重复启动。在 ZenMind 内新建报工仍会单独触发 `SyncEfforts()`，不受全局 ETL 锁影响。

系统配置页的**同步日志**记录每次增量同步与报工回刷（自动 / 手动 / 定时），含开始时间、耗时、成功或跳过原因。

## 版本号（Harbor / Docker Hub / GitHub / 界面）

仓库根目录 **[`VERSION`](../VERSION)** 为**唯一来源**，格式为 `v` + 多段数字（如 `v1.0.44`，需要时可为 `v1.0.44.1`）。前端侧栏展示的版本、Harbor 镜像 tag、推 Docker Hub 时的版本 tag、GitHub Release 标签应与此一致。

| 操作 | 命令 |
|------|------|
| 查看当前版本 | `./scripts/version.sh current` |
| 发布前 patch +1 | `./scripts/version.sh bump patch` |
| 次版本 / 主版本 | `./scripts/version.sh bump minor` / `major` |
| 手动指定并同步 | `./scripts/version.sh set v1.0.45` |
| 打 Git 标签 | `./scripts/version.sh tag-git`，再 `git push origin <tag>` |

Harbor 构建推送（本机 `harbor-manager.sh`）：

- `./harbor-manager.sh auto all "说明"` — 先对 `VERSION` 做 patch +1，**前后端使用同一 tag** 构建并推送，并更新 `.harbor-versions`。
- `./harbor-manager.sh build-push all "$(./scripts/version.sh current)"` — 使用当前 `VERSION`，不自动递增。

推 **Docker Hub** 时请使用**已在 Harbor 验证通过**的 tag（与 `VERSION` 一致），勿在推 Hub 时单独再 +1。

- `./scripts/dockerhub-publish.sh` — 默认先对 `VERSION` 执行 `patch +1`，再构建并推送前后端，同时更新 `latest`。
- `./scripts/dockerhub-publish.sh backend` / `frontend` — 仅发布单个服务。
- `./scripts/dockerhub-publish.sh all v1.0.58` — 指定 tag 发布。
- `./scripts/dockerhub-publish.sh all "$(./scripts/version.sh current)"` — 使用当前 `VERSION` 发布（不递增）。

也可以使用 GitHub Actions 发布：`.github/workflows/dockerhub.yml` 支持手动输入 tag 发布，或在推送 `v*` Git 标签时自动发布。仓库需要配置 `DOCKERHUB_USERNAME` 与 `DOCKERHUB_TOKEN` 两个 secrets。

## Docker 与部署要点

- **编排** [`docker-compose.yml`](../docker-compose.yml)：默认拉取 Docker Hub 上的 **`${DOCKERHUB_NAMESPACE:-techxtry}/zenmind-{backend,frontend}:${ZENMIND_IMAGE_TAG:-latest}`**；使用者只需该文件与 `.env`（见 README「最快上手」），无需整仓源码。数据库迁移由后端镜像内嵌 SQL 在启动时执行。
- 从源码构建：叠加 [`docker-compose.build.yml`](../docker-compose.build.yml)，生成 `zenmind-backend:local` / `zenmind-frontend:local`（见文件内说明）。
- 为减少“端口已被占用”类启动问题，Compose 中 **PostgreSQL / Redis / backend 默认不发布到宿主机端口**（仅容器网络内可访问）；对外只发布前端端口（默认 `2024`，可通过 `WEB_PORT` 覆盖）。
- **后端镜像**：工作目录 `/app`，镜像内已含 `config/etl_tables.yaml`；Compose 通过环境变量注入 `PG_DSN`、`REDIS_ADDR` 等。
- **前端镜像**：Nginx 将 `/api` 转发到 **`http://backend:8080`**，编排中服务名为 `backend`（见 [`frontend/nginx.conf`](../frontend/nginx.conf) 中的 `proxy_pass`）。

单独构建示例（在项目根目录）：

```bash
docker build -f backend/Dockerfile -t zenmind-backend:latest ./backend
docker build -f frontend/Dockerfile -t zenmind-frontend:latest ./frontend
```

生产环境若使用私有镜像仓库，可将 `DOCKERHUB_NAMESPACE` 指向自有命名空间，或自行编写 `docker compose` 覆盖 `image` 并配置 `docker login`。

## HTTP API（摘要）

- `POST /api/login` — 登录
- `GET/PUT /api/config/datasource`、`POST /api/config/datasource/test` — 数据源（需 JWT）
- `GET/PUT /api/config/sync-settings` — 自动同步周期间隔（分钟，需 JWT）
- `GET /api/users`、`/api/groups` 相关 — 用户与小组
- `GET /api/workbench/*` — 工作台列表
- `POST /api/sync/trigger`、`POST /api/sync/effort-reconcile`、`GET /api/sync/status`、`GET /api/sync/logs` — 同步与执行日志（写操作与日志需管理员；`effort-reconcile` 为报工回刷）

具体路由定义见 [`backend/cmd/server/main.go`](../backend/cmd/server/main.go)。
